# Legacy SkyShield update descriptor

Current deployments use [the host update script](../docs/16-系统更新.md), which
resolves the latest official GitHub release and its images directly. This
descriptor is for older deployments that still have the web updater.

`stable.json` is generated by `scripts/publish-update.py` after publishing all
four immutable `sha-<source commit>` image tags. Its absence means no supported
automatic-update release has been announced yet; clients show that state
without calling it a failed version check.

The descriptor binds one source commit and the public Server, Frontend,
Bootstrap and Nginx image digests. The LunaFox Agent remains the original
upstream image specified in that source commit's Compose file.

Publisher sequence:

1. Commit the complete source change. Build the four images from that commit
   with `org.opencontainers.image.revision=<full commit>` and publish their
   `sha-<first 12 characters>` tags.
2. Run `python3 scripts/publish-update.py --revision <full commit> --version <release version> --notes <release notes file>`.
   The command reads public registry metadata and rejects missing images,
   mismatched revisions, invalid platforms or digests.
3. Commit `updates/stable.json` separately and push it to `main`. Keep that
   channel-only commit limited to `updates/` so local installs can identify
   the source revision shared with the Docker release.
4. Retain released digest references. Do not remove blobs still referenced by
   a published descriptor or supported deployment.

Clients trust the fixed SkyShield GitHub HTTPS channel and confirm the source
commit and image digests. This is not a signature-based release infrastructure.
