# Organization asset monitor

`GET /v1/assetMonitors/current?organizationIds=1,2` is an authenticated, selected-organization projection of the unified asset library. It requires active default-tenant membership and 1–50 distinct, existing organizations. Missing/deleted organizations fail the request; an invalid selection never falls back to a global view.

Organization-to-target and asset bindings are deduplicated before counting. Direct organization observations are included. The dashboard counts unique subdomains, IP addresses and host:port pairs; HTTP and HTTPS default to ports 80 and 443 and URL paths do not create extra assets. Domain:port and IP:port are separate identities. Shared assets count once in the overall totals and once within each organization that owns a binding. Removed targets and their observations are excluded. Risk and scan data use the same selected, active target set. Seven-day charts are actual discovery counts, not synthesized historical inventory totals.

`assetTypes` and `assetCategories` retain canonical record counts for existing clients. `inventoryCategories`, the totals, locations, per-organization counts, recent discoveries and trend all use the deduplicated inventory described above. The five highest exposed ports count unique host:port identities in the selected organizations. The global overview uses the same inventory projection. Raw URL and service records remain unchanged.

`recentAssets` returns up to 50 unique inventory identities, newest `firstSeenAt` first, with category and label as deterministic tie-breakers. A smaller scoped inventory returns only its actual records. The display scrolls this returned list without adding placeholder assets.

Derived root domains remain available in the asset library but do not count towards the monitoring inventory unless a concrete host:port is observed. This projection does not widen any scan target.

Each inventory identity has at most one map location: a successful recorded-public-IP location takes priority, followed by the current public DNS answer's location, then recorded FOFA country information. DNS is explicitly labeled as an estimate and is not proof of the scanned IP, an open port, or reachability. Country locations are explicitly country-level. Unknown, private-IP-only, and proxy Fake-IP-only assets stay unlocated. Assets on multiple IPs are not counted several times.

IP enrichment reuses the process-wide geolocation coordinator and its rate, queue, cancellation, and single-flight bounds. At most 16 due public IPs and 16 hostnames are admitted per dashboard read; database admission prevents repeated attempts across polls. DNS uses HTTPS through the system HTTP proxy to `dns.google`, excludes IP literals and reserved local names, and accepts only public IPv4 answers. DNS successes refresh after one hour, and failed lookups retry after 15 minutes; stale estimates remain labeled. Geolocation success lasts seven days; old successes remain visible as expired, and failures retry after 15 minutes. Private and proxy-generated IPs receive only a seven-day scheduling suppression entry and are never sent to the geolocation provider. Responses do not depend on provider availability. Enrichment uses the application lifecycle, never the short HTTP request lifecycle. Only successful public IPs receive coordinates; no target credentials are stored in the cache.

Frontend: `/asset-monitor/` owns selection; `/asset-monitor/screen/?organizations=1,2` is an authenticated, standalone new-tab canvas. It shares the normal session renewal and upgrade boundary while omitting ordinary navigation chrome.

City metadata is persisted with successful GeoIP coordinates. IP and DNS locations expose provider country/region/city names and group at four-decimal coordinate precision, keeping distinct city labels separate. Country-only evidence remains country-level. Migration 000077 retains existing coordinates and makes old successes eligible for one gradual metadata refresh through the existing queue. A missing city remains explicitly unavailable rather than being inferred from a country centroid. Country-only fallback does not block subsequent DNS/IP enrichment.
