# Unified asset registry

The persistent `assetType` identifies the existing service or endpoint record. The user-facing `displayType` classifies HTTP/HTTPS services and URL endpoints as `web`; non-HTTP services remain `service`. Inventory queries can use `assetCategory=web` or `assetCategory=non_web_service`, with category bound into the pagination cursor. The existing `assetType=service` query still returns the canonical service family. URL bytes, source bindings, asset IDs, and scan results are preserved.

Root-domain assets use the same `(tenant, type, canonical identity)` as explicitly registered roots. A domain target or a subdomain, service, or endpoint asset can provide a derived source. Hosts are normalized through the result contract and reduced with the Go public-suffix list, including private suffixes. IP addresses, bare public suffixes, invalid hosts, and single-label names do not produce roots.

The root projection is an informational inventory association. It does not create a scan target or widen a target's permitted scope. A target-scoped lookup only includes a derived root when that target itself is the same root domain; a narrowly scoped subdomain target does not grant access to its parent domain. Root identities link to an overview of related assets without a derived badge.

Root coverage graph and reference views reuse inventory visibility and organization filters. They read persisted assets only and never start scans. Confirmed coverage requires a confirmed fact from a readable, non-deleted AI task with coverage enabled. References preserve source task IDs and remain owner-scoped even when the asset is shared. Graphs are bounded to 5,000 nodes and references to the latest 200 rows with explicit truncation indicators; ports without canonical identities do not acquire an asset ID or implied AI evidence.

Migration `000028_root_domain_projection` installs a durable append-only queue for new/updated asset identities and domain targets and seeds resumable cursors for historical data. `RootDomainController` processes both streams continuously in bounded transactions, with a transaction advisory lock to serialize projection across server instances. The append-only queue prevents source writes from waiting on a projection's locked event; newly committed changes always retain their own event. The worker re-reads queued records and commits mappings with removal of only the selected event IDs. Legacy asset backfill may run concurrently; its new identities enter the queue.

Derived root visibility follows live sources. Soft-deleted targets, deleted source bindings, and removed target observations do not keep a root visible by themselves. A root explicitly registered independently remains visible even after derived sources disappear. Projection never deletes an existing root asset, preserving explicit registrations, identities, and other references. Organization monitor links include derived roots for the selected organizations and may inherit geographic evidence from their linked source assets.

First/last seen timestamps in the inventory also account for currently visible child assets. A repeat scan may update a child's observation timestamps without changing its identity and without flooding the projection queue.

The asset interface supports organization and root-domain scoping, exact totals and direct page numbers while the existing cursor contract remains available. The combined inventory includes canonical assets and distinct host:port rows; it does not invent asset IDs for ports. Port rows include active scan mappings, service/URL records, and registered IP open-port observations. Explicit service observations take precedence; names inferred from well-known port numbers are labeled as estimates rather than confirmed protocols. Shared assets retain their organization associations, and deleted targets do not keep a scope link alive.

Application discovery is a bounded, durable projection of existing website evidence, not an active network scan. Specific non-error page titles or an allowlisted product fingerprint form candidates; generic pages and failed responses do not. Equal normalized names under the same registrable root are grouped, while each website keeps its own evidence. Organization and target scopes follow the original website bindings. A manual application with the same name, a bound domain under the same root and an overlapping organization or target is reconciled with that group; ambiguous matches are not guessed. Migration `000032_application_discovery` installs an append-only website queue, a resumable manual-association queue and historical cursors. When evidence disappears the link is removed but the application identity is retained for existing references and is hidden unless still independently registered or associated with a visible website. Recognition does not expand a task's authorized target.
