# 扫描实时保存与 URL 提速

有效观测通过现有类型化结果接口持续提交。公共 SDK 在每秒、达到批次数量或字节上限、结果流关闭时刷新非空批次。Server 每次确认仍代表该批 Snapshot、资产投影与统计已在同一事务提交。扫描后续失败、超时或取消时，已确认的结果保留；取消后不绕过任务权限补写未确认数据。

子域名阶段只发布解析验证后的域名，不把未经验证的枚举候选作为解析结果。端口、网站、目录和 URL 阶段读取工具输出的完整记录并持续提交，半行输出不会提前解析。指纹、截图和漏洞阶段沿用已有流式提交，由公共定时刷新避免小批次等待至扫描结束。工具自身在结束时才写出的结果，只能在其实际产出后保存。

URL 收集默认使用响应状态为 2xx/3xx 的站点入口，仍保留目标基线。失败或受保护站点保留在资产中；需要完整抓取时将 Katana 的 `seed-policy` 改为 `all`。入口按原协议、主机和端口保留，不把不同端口的应用合并。

Waymore 与 Katana 并行收集。URL 每批最多 128 条，批次准备好后立即清洗、验证和保存，不再等待所有采集器完成。最近 8,192 个 URL 的摘要用于减少重复验证，缓存淘汰只会允许重查，不会漏掉独有 URL。每 10 秒上报发现量、验证量和运行时长。

默认参数为：单入口抓取时限 120 秒、同时处理 10 个入口、深度 2、请求超时 5 秒、请求重试 0 次。Waymore、Katana、Uro、HTTPX 的进程预算分别为 300、1800、300、900 秒。流水线总预算为最长采集预算加清洗、验证预算，默认 50 分钟；这是硬性预算，不是预计完成时间。预算限制会影响覆盖率，可按需要调整；进程失败仍会如实标记任务失败，之前确认的数据保持可见。

扫描详情在任务运行时每 3 秒刷新当前可见的结果和统计，资产列表每 5 秒刷新。浏览器隐藏页签不做后台轮询。

本地启动脚本会构建原生引擎，并通过仅允许在单机模式使用的本地包更新命令安装变更的配置。原生包使用独立的 `native.invalid` 引用，不代表 Docker 发布产物；Docker 部署需要按原有流水线重新构建并发布引擎镜像与包。历史任务保存的执行计划不会被改写。
