# 本地单机部署

单机模式在本机以进程方式运行 Server、前端、PostgreSQL、Redis、扫描 Agent 和扫描引擎，不需要 Docker。启动脚本为当前数据库自动创建本机扫描 Agent，之后复用同一个身份和凭据。

## 环境要求

- Linux `amd64` 或 `arm64`，以及 Go 1.26.10、Node.js 22、pnpm、Python 3。
- PostgreSQL 客户端及服务端程序（`pg_config`、`initdb`、`pg_ctl`、`psql`、`createdb`），以及 `redis-server`。
- `curl`、`git`、`gcc`、`make`、`tar`、`unzip`、`sha256sum`；截图功能需要 Chromium 或 Google Chrome。Python 需要 `uv` 或可用的 `venv`/`pip`。
- 首次构建需要访问 Go、Python、Rust 和上游工具的下载源。脚本将 Rust 和扫描工具安装在本项目的本地数据目录中。

## 启动和停止

在项目根目录执行：

```bash
./local.sh start       # 首次部署、更新源码后重新构建
./local-start.sh       # 启动已部署的服务
./local-restart.sh     # 重启已部署的服务
./local.sh status      # 查看进程状态
./local.sh stop        # 停止服务
```

日常启动和重启不会编译程序或安装扫描工具，需要先成功执行一次 `./local.sh start`，并使用首次部署的同一系统用户运行。这两个脚本分别等价于 `./local.sh run` 和 `./local.sh restart`，可附加 `--ui-only`，使本次启动不启动扫描 Agent；如果 Agent 已在运行，启动命令不会停止它。重启会中断正在执行的任务；数据、密钥和扫描记录会保留。

升级到最新正式版本请运行 `./update.sh --mode local`。手工切换开发源码后，使用 `./local.sh start --no-tools-install` 重新构建；若扫描工具尚未安装，则使用 `./local.sh start`。

如果前端构建提示 `JavaScript heap out of memory`，可在可用内存足够时临时提高 Node.js 堆上限，例如：`NODE_OPTIONS=--max-old-space-size=4096 ./local.sh start --no-tools-install`。

首次启动会构建本地程序和八个扫描引擎，初始化数据库、默认字典和指纹数据，并安装缺失的扫描工具。前端监听 `0.0.0.0:3000`，本机访问 `http://127.0.0.1:3000`，其他设备可访问 `http://服务器IP:3000`。已有本地数据不会因重复启动被重新初始化；单机 Agent 注册使用独立的数据库绑定和 mode-0600 凭据文件。已运行的旧版本需先执行 `./local.sh stop`，再执行 `./local.sh start` 应用新的监听地址。

启动 Agent 后，当前实例中符合领取条件的等待任务会自动执行。单机 Agent 一次运行一个扫描子任务，后续阶段按工作流依次放行。

可选参数：

```bash
./local.sh start --no-build          # 使用已有构建产物
./local.sh start --no-tools-install  # 缺工具时报告错误，不自动安装
./local.sh start --ui-only           # 只启动界面和 Server，不领取扫描任务
```

默认数据目录为 `.local/dev-runtime`，可通过 `SKYSHIELD_LOCAL_DATA_DIR` 指定绝对路径。默认端口为前端 `3000`、Server HTTP `8080`、Server gRPC `9090`、PostgreSQL `41303`、Redis `51563`，分别可通过 `SKYSHIELD_LOCAL_FRONTEND_PORT`、`SKYSHIELD_LOCAL_HTTP_PORT`、`SKYSHIELD_LOCAL_GRPC_PORT`、`SKYSHIELD_LOCAL_PG_PORT` 和 `SKYSHIELD_LOCAL_REDIS_PORT` 修改。`SKYSHIELD_GO` 可指定 Go 可执行文件。执行工作目录默认为 `/tmp/skyshield-<uid>-engines`，可通过 `SKYSHIELD_LOCAL_EXECUTION_ROOT` 修改；路径必须归当前用户所有且权限为 `0700`。

脚本只停止由自身记录并确认身份的进程，不删除数据库、组织、扫描记录或密钥。若 Agent 凭据文件丢失或与数据库绑定不一致，启动会报错并要求修复，避免自动创建重复身份。

需要完全放弃旧数据重新安装时，使用 `./uninstall.sh --mode local --purge --dry-run` 预览，
再执行 `./uninstall.sh --mode local --purge --yes`，最后运行 `./local.sh start`。
此操作会删除数据库、密钥、Agent 身份、本地工具、前端依赖和构建，
参见[卸载与干净重装](17-卸载与干净重装.md)。

当本机 Agent 正在扫描时，`start` 不会为了应用新构建而重启它；请在任务结束后再次启动。`stop` 会中断当前执行的子任务。

更新源码后的前端先在独立目录构建，并在临时本地端口启动检查；候选构建失败时不会停止正在运行的服务。Server、Agent 和引擎也先全部构建到临时目录，在确认没有正在执行的扫描后才替换可执行文件。前端正式切换失败时，脚本尝试重新启动原前端；数据库迁移和后端启动分别按日志报告。成功切换后，`--no-build` 使用上一次通过检查的前端构建。候选目录及预启动日志会保留，日志位于 `.local/dev-runtime/logs/local-frontend-preview.log`。

## 本地运行边界

正式版本通过部署主机上的 `./update.sh` 更新，参见[系统更新说明](16-系统更新.md)。

本地进程使用部署机原有网络空间，沿用其路由、VPN、hosts 和 DNS；环境代理变量在进程
启动时继承，平台内已显式设置的代理策略继续优先。默认解析器资源现在跟随系统 DNS，
优先使用活动的 systemd-resolved 以保留分域解析。只有未编辑的原始默认 `resolvers.txt`
以及本项目先前生成、未被人工改动的内容会自动同步，自定义解析器列表不会被覆盖。
可通过 `SKYSHIELD_HOST_RESOLV_CONF` 指定 DNS 配置文件，或通过
`SKYSHIELD_SYSTEM_RESOLVERS_FILE` 指定只含 DNS IP 的列表；无可用 DNS 时明确报错，
不会自动切换到公网 DNS。`SKYSHIELD_SYSTEM_DNS=0` 关闭默认解析器资源同步。
变更代理环境后需重启对应进程；虚拟机内的本地部署使用虚拟机的网络，不能代替虚拟机
接通物理电脑上的 VPN。

- 本地 Server HTTP、gRPC 和前端监听所有 IPv4 地址；PostgreSQL 和 Redis 仍使用本机回环地址。扫描引擎以当前用户身份运行，使用独立临时目录和私有通信 socket；此模式不提供容器隔离，适用于开发和测试。请根据实际访问范围配置主机防火墙。
- 每次启动扫描子任务时，Agent 从本机 Server 获取当前 HTTP/HTTPS 代理策略；Server 的数据库和模型凭据不会传入引擎环境。
- 扫描任务进度和结果写入原有数据库。本地模式不要求 Loki；未单独启动 Loki 时，依赖 Loki 的系统/Agent 分布式日志查询不可用。可通过 `SKYSHIELD_LOCAL_LOKI_URL` 指向本机运行的 Loki，进程日志保存在 `.local/dev-runtime/logs/local-*.log`。
- `./update.sh --mode local` 编译安装正式版本，并在部署主机保存备份和操作记录。

### 内置反连端口

反连 HTTP 默认独立监听 `0.0.0.0:8899`，Web 界面继续使用 3000。默认本机探针地址为 `http://127.0.0.1:8899/oast/<令牌>`。远程测试须通过 `OAST_PUBLIC_URL=http://目标可达的服务器IP:8899` 指定入口；需要其他端口时设置 `OAST_HTTP_LISTEN` 并同步网络映射。仅使用 Web 反向代理入口时可设置 `OAST_HTTP_LISTEN=off`。已有探针保持原地址，新创建的探针使用新配置。
