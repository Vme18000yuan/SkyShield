## 本地构建

后端使用 `server/go.mod` 声明的 Go 1.26.10；前端使用 `packageManager` 声明的 pnpm 10.30.3。

```bash
cd server
go build -o bin/server ./cmd/server
make check-architecture
go test -short ./internal/airuntime ./internal/modules/assetregistry/... ./internal/modules/aiworkbench/... ./internal/modules/aisettings/...

cd ../frontend
corepack pnpm install --frozen-lockfile
corepack pnpm typecheck
corepack pnpm check:ui-foundation
corepack pnpm build
```

数据库迁移新增 `000010`～`000022`，保留上游 `000001`～`000009` 字节不变。`000021` 将探索图锚定资产回填到任务资产关系，并保持后续新增锚点同步；`000022` 保存加密 FOFA 配置、查询快照与幂等同步账本。执行降级文件只用于隔离测试拆除。可运行 `TIANQIONG_GO=<Go 路径> bash scripts/test-postgres-contracts.sh` 自动创建并销毁独立的临时 PostgreSQL 测试集群；不要将迁移集成测试指向业务数据库。任务工具历史在执行标识引入前的旧记录不会猜测配对结果。

任务 MainAgent 复用 ARTEX 的分段 transcript 和 `main_sessions`，通过任务活动记录保留用户消息、回复和工具步骤。运行时只开放经过宿主白名单筛选的探索图工具及已授权平台工具；Bash、文件工具和 WebFetch 不会通过任务聊天启用。

任务 MainAgent 使用同一用户的 `assistant` Agent 设置、平台工具授权、Skill 与 MCP 绑定；它只连接当前持有有效租约的本机任务运行实例。任务暂停或进入终态后，发送消息返回冲突，现有运行控制边界不会被聊天入口绕过。

AI 计划绑定已有 AI 任务，计划窗口是对同一个任务的运行控制，不会在每次窗口创建新任务。多个计划按开放窗口并集计算；人为暂停不会被计划自动恢复，用户选择“立即运行”时可以显式恢复。服务实例竞争时由 PostgreSQL 协调，并在任务领取前复核窗口。

## AI 配置

建议使用“系统 → AI 设置 → LLM”管理模型。配置接口仅允许默认租户的活动管理员访问；普通模型调用只需具备租户成员身份。

“系统 → AI 设置 → Agent 设置”配置内置对话助手、规划者和执行者，配置在新运行开始时读取；正在执行的运行不会热更新。规划者与执行者的步数为 0 时跟随任务预算，对话步数为 0 表示不限；对话和执行者单次时间为 0 时表示不限，但任务总时间预算仍然生效。这里尚未实现 ARTEX 的自定义 Agent、独立模型绑定、触发器和完整提示词模板管理。

“系统 → AI 设置 → 工具设置”目前管理 `search_platform_assets` 和 `insert_assets` 的逐 Agent 授权；任务探索图工具和宿主执行器不属于此处的可配置目录，ARTEX 的自定义工具与 MCP 工具绑定尚未迁移。

“系统 → AI 设置 → Skill 设置”支持文本指令的创建、修改、删除、启停及 Agent 绑定，按 Norma 的 `Skill` 工具按需加载，已启动的运行使用启动时快照。当前不支持上传文件包、脚本执行、Skill 使用统计及 MCP 按需解锁。

“系统 → AI 设置 → MCP”支持远程 Streamable HTTP 服务器、Agent 绑定、工具发现及连通测试；请求头使用同一持久加密密钥保存，接口不返回明文。每次 Agent 运行按绑定连接并释放客户端，模型通过 ARTEX 的延迟工具发现和调用路径使用工具。当前不支持 stdio、旧版 SSE、Skill 触发解锁以及完整人在环路审批；启用 TLS 校验跳过选项仅用于用户明确选择的服务器。

| 环境变量 | 用途 |
| --- | --- |
| `TIANQIONG_AI_ENCRYPTION_KEY` | Base64 编码的 32 字节密钥 |
| `TIANQIONG_AI_ENCRYPTION_KEY_FILE` | 上述密钥的文件路径；与明文环境变量二选一 |
| `TIANQIONG_AI_DATA_ROOT` | 持久化会话及工作目录的绝对路径 |
| `TIANQIONG_LLM_PROVIDER` | 可选环境配置：`openai` / `openai-responses` / `anthropic` |
| `TIANQIONG_LLM_API_KEY` | 可选环境配置的模型密钥 |
| `TIANQIONG_LLM_MODEL` / `TIANQIONG_LLM_BASE_URL` | 可选环境配置的模型及接口地址 |

数据库默认模型优先于环境模型。兼容 ARTEX 原有环境解析，但不运行其独立 Web/API 或 `db.Open` 初始化。

加密密钥需要持久保存；随意更换会导致已有模型凭据无法解密。普通 API 不返回明文 Key 或密文。UI 更新时留空 Key 表示保留已有凭据。

## Compose 源码构建与现有部署保护

新增 `compose.tianqiong.yaml` 使用天穹源码构建 Server、Frontend 和 Bootstrap，保留原 Agent/Engine 合同。开发密钥准备脚本只创建缺失文件，不覆盖已有密钥：

```bash
bash scripts/tianqiong-dev-init.sh
docker compose -f compose.tianqiong.yaml config --quiet
docker compose -f compose.tianqiong.yaml build
```

闭源 LunaFox Agent 固定依赖 `lunafox_data` 等 daemon 级卷名。当前宿主机已有原 LunaFox 卷，因此 `tianqiong-volume-preflight.sh` 会拒绝将其挂载到新项目。完整栈应在独立 Docker daemon 中验收，不应手工删除原卷或绕过归属检查。

`compose.yaml` 是上游部署快照，仍引用上游发行镜像；它不是当前天穹源码的部署入口。新的 Compose 全栈启动和完整扫描尚未验收，源码构建成功不等同部署验收成功。
