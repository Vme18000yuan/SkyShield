# AI 对话与长任务执行可靠性

本次整改覆盖对话、任务编排、模型调用、本地工具、MCP、会话检查点及前端回放。
新增迁移为 `000076_ai_execution_reliability`；原有迁移保持不变。

## 运行行为

- 独立对话的运行时长预算覆盖准备阶段、模型和工具调用。预算到期后最多使用 30 秒收尾；等待本地会话锁和工具通信写入也可取消。
- 模型默认首个有效响应等待 120 秒、流式空闲等待 120 秒、单次调用上限 600 秒。空 keep-alive 不无限延长等待。四项模型配置（含并发）可在 LLM 设置中修改，0 表示使用默认值。
- 单次原始模型响应限制为 16 MiB；超限返回错误并保留已确认的工具记录，不重放已产生输出的调用。
- Transcript 读取失败会阻止模型继续；写入失败会终止本轮。工具在实际执行前写入意图日志，结果另行确认。重建历史时保留缺失结果的调用，并明确其效果不确定。重复的工具调用 ID 按具体执行关联，不能用旧结果覆盖新的未确认执行。
- 数据库已有历史而对应文件缺失时拒绝静默创建空会话。同一任务在本实例的两轮运行串行交接，旧运行完成清理后才启动恢复执行。
- Transcript 追加会同步落盘。损坏历史不自动丢弃或覆盖，应保留原件后从可验证备份修复。普通首次会话仍可正常创建。
- 停止请求先进入 `stopping`，执行器确认结束后进入 `stopped`。租约失效、超时、步数/调用预算耗尽和失败分别展示；复测与发现审查的终态投影同样等待确认。
- 前端通过 `finalCursor` 与 `hasMore` 补齐全部尾页，后台结束不意味着停止补拉。模型文本使用有界实时预览，完整消息仍单独存储。
- 长会话最多缓存 2000 条活动，较长列表使用虚拟渲染；查看历史时可通过“回到最新”重新加载尾部。
- 侧问快照采用每个来源保留最新值的有界后台写入，模型调用不等待慢数据库写快照。关闭运行前有有界排空；侧问继续显示快照时间，并使用数据库核实主运行状态。

## 调度与容量

Planner 运行在独立 goroutine 中，协调循环继续派发普通 Worker、处理完成事件和取消。
规划结果只确认它实际处理的人工事件；运行中的新变化合并到下一轮。Worker 的重试共用
本次意图的时间预算，不因重试重新获得一份完整时间预算。

PostgreSQL 执行许可默认值如下，可在 AI 运行配置中调整：

| 范围 | 默认值 | 最大可配置值 |
| --- | ---: | ---: |
| 全局执行（对话、任务、侧问、工具测试） | 16 | 16 |
| 每用户执行 | 8 | 16 |
| 全局模型调用 | 32 | 64 |
| 每用户模型调用 | 8 | 64 |
| 单个模型配置 | 4 | 64 |
| 全局工具运行器 / MCP 连接 | 16 | 16 |
| 每用户工具运行器 / MCP 连接 | 8 | 16 |

执行许可使用事务锁、45 秒租约和 10 秒续租，跨服务实例共同计数。续租失败会取消执行。
工具运行器/MCP 容量至少为 2，约四分之一预留给阶段执行、脚本和审查上下文读取，避免常驻连接占满后阻塞自身的子步骤。
模型调用在容量不足时等待；新独立对话容量不足返回 HTTP 429。停止操作不需要取得许可。
原任务并发开关默认开启，上限 5；关闭该开关仍受系统容量上限约束。

每个任务图连接池最多 2 个连接，空闲保留 1 个，为控制 API 和心跳保留连接空间。
本地执行器最多同时接收 8 个普通工具请求，并为任务查询/停止保留 2 个名额。
配置级 RPS/RPM 仍使用进程内滑动窗口；多实例部署需要外部统一出口限速或进一步共享速率账本。

整轮模型保护预算（所有子调用共享，实际 HTTP 重试同样占用请求预算）：

| 运行 | HTTP 尝试上限 | 输入与输出 Token 合计上限 |
| --- | ---: | ---: |
| 独立对话 | 默认不限（0） | 默认不限（0） |
| 自主任务的一次运行 | 默认不限（0） | 默认不限（0） |
| 任务 MainAgent 独立交互 | 默认不限（0） | 默认不限（0） |

独立对话的累计 Token、模型请求次数默认均不设限，工具调用轮数默认也为 0（不限）。可在 AI 运行配置中显式设置 `chat_run_max_tokens`、`chat_run_max_requests`；自主任务与任务内对话通过 `task_run_max_tokens`、`task_run_max_requests` 配置，同样默认 0（不限）；统一经运行预算入口解析，任务内子调用共享预算，不再在执行器中设置固定阈值。上述累计预算与 Agent 运行时长、单次 API 超时、上下文窗口和并发控制相互独立。配置在下一次运行生效。

显式预算耗尽时使用 `run_budget` 终态，不当作 API 故障重试或切换模型；另有最多 16 次请求、1,000,000 Token 的收尾额度，并受原收尾时间/轮数限制。输入 Token 已包含缓存命中，不能再叠加缓存读写。新的对话消息使用新的运行预算并恢复原会话记录，已完成的工具调用不自动重放。未配置模型窗口时使用保守的 32K；大窗口模型应填写
实际容量。任务模型链与全局模型池使用候选模型的最小窗口，内置压缩器会跟随运行中的窗口变化。
未设置输出上限时，托管调用预留最多 8192 Token，且不超过配置窗口的四分之一。

## 执行与恢复边界

工具可写目录限定到当前会话或当前任务；工具测试使用独立目录。Skill 及共享采集证据通过只读授权访问。
MCP 与自定义脚本遵守相同的工作区边界。信息收集仍使用原有阶段检查点续接。

后台命令原始输出及启动/结束检查点保存在工作区 `.task-output/`，执行器退出不会删除这些证据。
只有结束检查点确认进程结果；缺少结束检查点的执行不能视作成功。旧任务编号不能重新连接一个
已经退出的进程，恢复时先检查已有证据和阶段状态，不自动重放有副作用的命令。

通用后台进程仍会随所属执行器结束而停止。本次实现了持久证据和安全的中断恢复边界，
没有将任意 Shell 进程变成可跨主机迁移、自动接管的远程作业。

## 生产资源隔离

Linux Landlock 提供文件访问控制。单文件写入上限为 256 MiB；工作区默认 1 GiB，启动前检查、
运行期间每 10 秒复核，默认最多 100000 个文件/目录，目录读取分批进行。
容量检查不自动删除已有证据；它不是文件系统硬配额的替代品。

生产可为 Server/独立工具二进制配置委派的 cgroup v2 子树：

```text
TIANQIONG_AI_CGROUP_ROOT=/sys/fs/cgroup/<delegated-subtree>
TIANQIONG_AI_REQUIRE_CGROUP=true
TIANQIONG_AI_WORKER_MEMORY_BYTES=1073741824
TIANQIONG_AI_WORKER_PIDS=128
TIANQIONG_AI_WORKSPACE_BYTES=1073741824
TIANQIONG_AI_WORKSPACE_FILES=100000
```

每个本地或 stdio MCP 进程在创建时进入自己的 cgroup，默认内存 1 GiB、128 个进程/线程、
2 个 CPU 的计算配额；关闭时清理整个进程组。启用 `REQUIRE_CGROUP` 后，目录未委派或限制写入失败
会拒绝启动执行器。普通开发环境不强制要求 cgroup。需要按宿主机总容量降低并发，不能只看单进程限制。

网络出口目标限制和硬磁盘配额仍应由部署网络/文件系统提供；Landlock 文件规则不会自动隔离网络。

## 升级与验证

1. 在独立数据库验证迁移和回归，备份现有数据库以及 AI 数据目录。
2. 停止旧版本接收新任务并完成退出；应用新增的 000076，再启动匹配的 Server 和 Frontend。
3. 容器构建同时复制本地固定的 `third_party/norma`，不修改 Go module cache。
4. 核对模型窗口及资源配额；生产启用 cgroup 时先验证宿主机委派。

现有 release-candidate 数据保留升级策略未放宽，不能绕过发布工具的迁移审核。
当前仍使用既有单租户资源范围；没有宣称完成多租户改造或多主机共享文件系统验收。

新增回归覆盖：模型无响应、历史损坏/写入失败、工具调用意图与结果恢复、调用 ID 重用、
工具通信写阻塞、后台输出保留、工作区越界、快照写入拥塞、超过 200 条的尾页补拉、
停止确认、并发许可超卖以及 Planner 等待期间的 Worker 派发。
