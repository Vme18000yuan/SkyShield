# AI 任务发现与漏洞管理

AI 任务的 `report_finding` 保存原始发现后，会同步到漏洞管理，并保留通往原始发现和 HTTP 流量证据的关联。AI 漏洞审查展示原始发现，供后续整理、归并和复核；它不是进入漏洞管理的审批门槛。新同步的记录标记为未复核，AI 的结论不会替代人工复核。

迁移 `000079_ai_task_vulnerability_projection` 修复了只识别 HTTP 服务、端点资产的问题：

- 已直接关联 Web 服务或端点的发现沿用原 URL。
- 关联子域名、根域名或 IP 的发现，可从其已绑定的 HTTP 证据提取真实 URL，优先采用证明漏洞的请求。URL 必须匹配发现的资产和任务目标，不从描述文本猜测地址。
- 只有域名、没有 HTTP 证据时，以 `dns://域名` 保留资产身份，不推测 HTTP/HTTPS 协议。
- 同步在事务提交时执行，确保同一次上报的请求、响应绑定已经保存。
- 升级时补录从未建立同步关联的历史发现。已有漏洞的人工复核、扫描来源、描述和原始数据不会被覆盖；重复执行不会新增重复记录，已被手工删除的漏洞不会自动恢复。

任务需要关联仍有效的目标。没有关联目标、没有可解析的资产或资产归属不匹配时，发现保留在 AI 任务中，不自动归入其他目标。删除或归档中的任务也不进行补录。原始证据和任务状态在同步过程中保持不变。

本地部署需重新构建 Server 并应用迁移；Docker 部署需使用包含该迁移的新 Server/Bootstrap 镜像。迁移不会主动访问目标或重新进行扫描。
