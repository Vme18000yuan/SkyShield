# AI 任务发现与漏洞管理

AI 任务的 `report_finding` 保存原始发现后，会同步到漏洞管理，并保留通往原始发现和 HTTP 流量证据的关联。独立的 AI 漏洞审查功能已停用；历史审查数据保留，漏洞整理、归并和人工复核仍可在现有页面完成。新同步的记录标记为未复核，AI 的结论不会替代人工复核。

迁移 `000079_ai_task_vulnerability_projection` 修复了只识别 HTTP 服务、端点资产的问题：

- 已直接关联 Web 服务或端点的发现沿用原 URL。
- 关联子域名、根域名或 IP 的发现，可从其已绑定的 HTTP 证据提取真实 URL，优先采用证明漏洞的请求。URL 必须匹配发现的资产和任务目标，不从描述文本猜测地址。
- 只有域名、没有 HTTP 证据时，以 `dns://域名` 保留资产身份，不推测 HTTP/HTTPS 协议。
- 同步在事务提交时执行，确保同一次上报的请求、响应绑定已经保存。
- 升级时补录从未建立同步关联的历史发现。已有漏洞的人工复核、扫描来源、描述和原始数据不会被覆盖；重复执行不会新增重复记录，已被手工删除的漏洞不会自动恢复。

任务需要关联仍有效的目标。没有关联目标、没有可解析的资产或资产归属不匹配时，发现保留在 AI 任务中，不自动归入其他目标。删除或归档中的任务也不进行补录。原始证据和任务状态在同步过程中保持不变。

本地部署需重新构建 Server 并应用迁移；Docker 部署需使用包含该迁移的新 Server/Bootstrap 镜像。迁移不会主动访问目标或重新进行扫描。

迁移 `000080_ai_vulnerability_display_names` 独立保存 AI 任务原始漏洞名称，API 通过 `displayName` 返回。列表分开展示漏洞名称与漏洞类型，详情标题使用漏洞名称；分类、去重键、漏洞 ID 和复核状态不变。多个 AI 发现映射到同一漏洞时，标题沿用创建该漏洞的原始发现；扫描器记录与人工修改过的名称不会被其他 AI 发现覆盖。

迁移 `000081_ai_conversation_vulnerability_names` 为独立 AI 对话的上报工具加入 `name` 字段，并让后续入库同时保存名称与类型。历史记录仅在名称为空、且能确认属于原始对话时补录：优先使用已保存的名称、原始报告标题或同一会话中唯一匹配漏洞 ID 的表格标签；没有独立标题时保留原来上报的标签，不从证据正文推测名称。已有名称、扫描结果和人工复核状态不被覆盖。
