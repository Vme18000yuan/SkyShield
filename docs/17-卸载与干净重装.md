# 卸载与干净重装

项目根目录的 `./uninstall.sh` 同时支持本地单机和 Docker 部署。默认卸载保留业务数据
与原密钥；`--purge --yes` 才会永久清除数据，适用于明确要放弃旧实例、从头安装的情况。
脚本需要 Linux 和 Python 3；清理 Docker 部署时还需要能连接原 Docker daemon 的 Docker CLI。

## 完全清除后重装

先在原项目目录预览清理范围：

```bash
./uninstall.sh --mode all --purge --dry-run
```

确认旧组织、资产、扫描记录、AI 数据、模型凭据和更新备份都可以删除后，执行：

```bash
./uninstall.sh --mode all --purge --yes
```

然后选择一种部署方式：

```bash
./docker.sh pull        # 拉取镜像，从空数据库重新部署
# 或
./local.sh start        # 安装本地工具与前端依赖，重新构建并初始化数据库
```

彻底清除会同时移除旧数据库与对应密钥，避免重装时出现旧数据库密码和新密码文件不一致的
`SQLSTATE 28P01`。重装仍需要满足网络下载、平台架构、系统依赖和端口要求；清理脚本不负责
安装 Docker、Go、Node.js、PostgreSQL 等系统软件。

只清除一种部署时，分别使用：

```bash
./uninstall.sh --mode docker --purge --yes
./uninstall.sh --mode local --purge --yes
```

## 清理范围

| 对象 | 默认卸载 | `--purge --yes` |
| --- | --- | --- |
| 本地 Server、前端、Redis、PostgreSQL、Agent 及其子进程 | 确认身份后停止 | 确认身份后停止 |
| Docker 项目容器、网络适配器、可确认归属的动态 Engine 容器 | 停止并移除 | 停止并移除 |
| Docker 项目网络，含由适配器建立的外部网络 | 移除 | 移除 |
| Docker 数据库、共享资源、Agent 身份、引擎执行、Loki、证书及升级状态卷 | 保留 | 删除 |
| `.local/secrets`、`.local/network` 和对应模式的 updater 状态、版本覆盖、更新备份 | 保留 | 删除 |
| 本地数据目录及其数据库、密钥、工具、日志、引擎和业务文件 | 保留 | 删除 |
| 本地扫描执行目录 | 保留 | 删除 |
| 本地前端 `.next`、候选构建、生成的候选 tsconfig、构建缓存、`node_modules` | 保留 | 本地模式清理时删除 |
| 源码、Git 仓库、`.env.example` | 保留 | 保留 |
| `.env` 等本机配置、应用镜像标签 | 保留 | 需额外指定下列选项 |

默认数据目录为 `.local/dev-runtime`，默认执行目录为 `/tmp/skyshield-<部署用户uid>-engines`。
清理保留 `.local/deployment.lock`，用于防止卸载和部署并发执行；空锁文件不包含部署状态，
不会影响重装。重复卸载可以继续清理上一次尚未移除的资源。

Docker 清理使用当前 Docker context，通过项目标签和精确资源名称识别本项目，不依赖成功
启动过的容器，也不依赖旧 Compose 覆盖文件可正常解析。默认项目名为 `tianqiong`，会读取
环境或项目 `.env` 中的 `COMPOSE_PROJECT_NAME`，也可通过 `--project-name` 明确指定。
已无容器的孤立卷、未带标签但名称完全匹配的残留卷也会清理。其他项目拥有的同名卷、
被其他容器使用的数据卷或网络会使清理停止，不会自动删除这些使用方。
旧版若曾将两种模式的更新记录放在同一 updater 目录，单独清理某种模式会保留另一种模式的
记录；`--mode all --purge --yes` 会清除整个共用目录。

## 清除本机配置和镜像

如果连访问地址、代理、网络模式和镜像标签配置也要恢复默认，可附加 `--remove-env`。
它会删除项目根目录、`server/`、`frontend/` 中的 `.env`、`.env.local` 和 `.env.*.local`：

```bash
./uninstall.sh --mode all --purge --remove-env --yes
```

如果还要删除缓存的 SkyShield 应用镜像标签，可附加 `--remove-images`：

```bash
./uninstall.sh --mode all --purge --remove-env --remove-images --yes
```

镜像选项仅清理 `solder110/skyshield-*` 和 `tianqiong-*` 的 Server、Frontend、Bootstrap、
Nginx 标签；PostgreSQL、Redis、Loki、上游 Agent/Engine 等依赖镜像与系统构建缓存保留。
脚本不执行全局 `docker system prune`，也不卸载机器上的共享系统依赖。

## 自定义目录与权限

本地部署应使用原部署用户和原目录设置。自定义目录可通过原环境变量传入，或明确指定：

```bash
./uninstall.sh --mode local --purge --yes \
  --local-data-dir /srv/skyshield/runtime \
  --execution-root /srv/skyshield/engines
```

脚本不能自动找到未记录的其他部署目录。自定义数据目录需要有本地部署标记，扫描执行
目录需要保持原部署要求的用户归属和 `0700` 权限；正在被其他实例使用的执行目录不会删除。
根目录、用户主目录、系统目录、源码目录以及通过符号链接重定向的运行目录会被拒绝。

Docker 操作和文件删除均需要相应权限；曾以 root 部署、产生 root 文件时，可在核对预览后
使用 `sudo ./uninstall.sh ...`，并显式传入原自定义路径。卸载会取得与部署、升级、工具安装
相同的锁，确认进程 PID、启动时间及路径或环境后再停止，避免误杀复用 PID 的其他进程。
如提示进程由其他方式启动，请先由原启动方式停止它，再重试卸载。

清理过程中任一步骤失败都会返回非零退出码。Docker 资源未清完时保留密钥和配置供重试；
只在出现“彻底清除完成”后重新部署。默认卸载后的重建则应继续使用原数据目录和密钥。
