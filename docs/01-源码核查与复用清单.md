## 5. 已确认的融合难点

### 5.1 当前并不是两套完整开源 Agent 源码

LunaFox 的 `agent/` 只有 `bin/sha256-…` 下的 AMD64/ARM64 可执行文件、bundle 清单、摘要和签名材料；[Agent Dockerfile](../../lunafox/docker/agent/Dockerfile) 直接封装这些产物。不能假设可以修改其内部算法、加入新的协议字段或重新编译。

第一阶段保留原扫描 Agent 协议和不可变产物；AI 通过 Server 应用接口提交原生扫描，由原节点继续执行。自研节点或新的执行协议是后续独立决策，不是本轮融合前提，也不绕过现有节点授权逻辑。

### 5.2 许可范围与构建范围需要独立核实

[LunaFox LICENSE](../../lunafox/LICENSE) 声明 `GPL-3.0-only`，同时明确其声明范围以及闭源 Agent 等排除项；不能据此直接推断本地 Server/Frontend 全部具有相同授权范围。[ARTEX LICENSE](../../ARTEX/LICENSE) 为 AGPL-3.0；`web/LICENSE` 还保留模板的 MIT 声明。

实施时保留原版权、许可和来源清单；在对外发行前核实 Server/Frontend 来源许可、闭源 Agent 使用与再分发边界以及组合代码的许可要求。本文记录源码事实，不据此作出完整发行授权结论。该核实不阻止当前架构设计和本地适配工作。

### 5.3 资产表、身份和证据语义不同

- LunaFox 通过 `target_id` 组织 `subdomain/host_port_mapping/website/endpoint/directory/screenshot`；另有每次扫描的快照。
- ARTEX `assets` 为六类统一资产：根域名、IP、子域名、应用、服务、接口；关联企业、任务、范围和探索节点。
- LunaFox Endpoint 的当前自然键为 `(target_id, url)`，无 HTTP method；ARTEX Endpoint 按 URL + method 去重。不能把未知方法猜为 GET。
- LunaFox 的域名表不含 DNS 记录类型和记录值；ARTEX 子域名包含这些字段。扫描中“未采集”不能写成空值覆盖已有结果。
- LunaFox HostPort 当前仅支持 IPv4，另有严格 host、port 约束；ARTEX IP 工具接受 IPv4/IPv6。IPv6 不可强写进旧表。
- LunaFox 把原始 URL 当不可变证据；ARTEX `normalizeURL` 会处理 scheme/host 及根路径尾斜线。融合时禁止把 ARTEX 的 URL 归一化函数直接放进旧观测写入链。
- `000008` 已把 Website/Endpoint 的状态码与内容长度扩为 BIGINT，并增加截断标志；设计不能只看初始建表 SQL，也不能把异常状态码按通常 HTTP 范围丢掉。

具体映射、未知值和回流方式见数据设计。

### 5.4 组织不是租户，现有鉴权不是完整企业权限

LunaFox `organization_target` 为多对多业务分组；JWT Claims 仅有用户和 TokenVersion 等信息，没有租户字段。[MCP 文档](../../lunafox/server/internal/mcp/README.md) 明确当前静态 key 具有部署级数据范围，组织不构成隔离边界。ARTEX 则使用全局管理员凭据与固定 JWT Subject。

天穹必须复用账号能力并新增租户/成员/角色/资源授权，不能只在前端藏菜单或给 HTTP Header 增加一个未校验的 tenantId。

### 5.5 多租户必须处理进程全局状态

ARTEX `ToolAugment`、`ToolResolve`、`PromptOverride` 是包级可变函数；PromptOverride 甚至没有 context 入参。直接为不同租户轮换这些全局函数会串配置并产生竞态。会话缓存、模型限流/健康注册表、工作目录、MCP 进程、流量代理和触发水位也需要租户维度。

这部分通过构造函数和运行上下文改造，保留内部执行算法；不能使用“处理请求前改全局变量、结束后改回”的适配办法。

### 5.6 独立对话与任务内对话必须同时保留

独立 ChatAgent 以 Norma 通用工具、绑定 Skill/MCP 为基础，不注入渗透任务图；MainAgent.Chat 则读写任务的图、目标、提示和执行方向。只实现其中一个不能满足 ARTEX 对话能力对等。

### 5.7 工具执行不是一个任意命令输入框

ARTEX 工具执行页面查询工具调用记录、按工具和关键字筛选、查看输入输出和统计，覆盖所有工具而不只是 Bash。当前 `db/commands.go` 查询任务 `activity`；独立对话活动另存在 `conversation_activities`。天穹保留历史查询语义，并用统一调用账本将两种来源纳入同一界面。

### 5.8 AI 计划不是扫描 Cron 的别名

ARTEX Calendar 管理已有任务的运行窗口，多计划共同绑定任务时计算开放窗口的并集，并保护人工暂停；窗口外暂停同一任务，而非每次创建新任务。Agent 事件触发器又是另一种语义。三类规则要统一治理，但不可互相替代。

### 5.9 扫描结果入口有真实执行授权栅栏

LunaFox ResultIngest 校验 Scan、Task、Target、Agent、Session/Epoch 并在事务中再次锁定和验证。AI 直接发现并不具有这些身份；必须走新的 AI 观测命令，不能伪造扫描任务或绕开栅栏。

### 5.10 Schema 不能直接拼接或重复初始化

LunaFox 当前迁移清单为 `000001`～`000009`；原始基线字节冻结。ARTEX `db.Open` 会创建连接、重跑 `schema.sql` 并 seed 数据；`llm_records/llm_usage` 等表还在其他 Go 文件内定义 DDL。移植时要统一清点，所有表结构进入天穹编号迁移，运行时 Seed 只初始化数据。
