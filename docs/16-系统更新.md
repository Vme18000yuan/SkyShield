# 系统更新

在 Linux 部署主机上，以原部署用户进入项目的 Git 克隆目录。确认任务已结束、原部署的
PostgreSQL 正在运行，然后执行：

```bash
./update.sh                 # 自动识别部署方式，显示目标版本并请求确认
./update.sh --mode local    # 本地编译部署
./update.sh --mode docker   # Docker 部署
```

同一目录同时有两种部署时，必须指定 `--mode`。无人值守维护可在命令后加 `--confirm`。
命令在前台运行，服务切换时应用会暂时不可用。无需在网页操作或安装更新服务。

脚本从 [SkyShield GitHub Releases](https://github.com/Vme18000yuan/SkyShield/releases/latest)
选择最新正式发布，按该标签获取源码。本地部署编译该版本；Docker 部署拉取相同源码提交的
四个 `linux/amd64` 镜像，并按摘要固定版本。如果配套镜像尚未发布，Docker 升级会在停机前退出。

## 已有部署首次使用

如果目录内的 `update.sh` 仍是旧版，先获取一个包含新版脚本的正式发布。在原部署目录执行以下命令，
把 `vX.Y.Z` 替换成 GitHub 上对应的发布标签：

```bash
git fetch --no-tags https://github.com/Vme18000yuan/SkyShield.git refs/tags/vX.Y.Z
git merge --ff-only 'FETCH_HEAD^{commit}'
./update.sh --mode docker   # 本地部署改用 --mode local
```

Git 操作只更新源码；原进程、配置和数据由升级脚本处理。源码需要干净且能快进；如果有本地修改
或分叉，先保存并处理。ZIP 下载目录需先按原部署方式备份配置、密钥及数据，并迁移成官方 Git 克隆。
已有旧更新服务会在升级时由脚本停止；如果是另一部署用户管理的服务，请由该用户先停止。

## 备份和验证

脚本在安装前校验源码、镜像、部署身份、待处理任务和备份空间。至少预留数据库大小加 10 GiB。
待应用停止写入后，脚本生成 PostgreSQL custom-format 备份，保存密钥和配置，再安装目标版本、
执行数据库迁移并检查服务就绪。Docker 模式保留数据卷，本地模式使用现有数据目录。使用自定义本地
端口或数据目录的部署须传入原部署使用的环境变量。

```bash
./update.sh status --mode local
./update.sh status --mode docker
```

状态命令只读取本机记录。Docker 记录存放在 `.local/updater/`，本地记录在 `.local/updater-local/`。
每次升级的 `operation-<操作ID>/` 目录含 `update.log`、`previous.json`、`target.json`。完成备份后，
目录还有 `database.dump` 和 `secrets/`。`previous.json` 分别记录升级前的检出提交和已部署提交。
备份包含数据库和配置，不包含上传文件、AI 工作区等文件型业务数据。
成功升级后保留最近一次成功备份以及本地当前和升级前的前端构建。失败的操作目录保留供恢复使用。

## 失败与恢复

停机前的失败可在处理原因后重试。如果已开始停机或安装，记录会标记为需要恢复。根据 `update.log`
决定向前修复或恢复升级前的版本。Docker 可参考 `previous-images.json` 或保存的 `compose.release.json`；
本地可参考 `bin/` 和 `frontend-build.json`。源码或程序回退不会回退数据库。需要恢复数据库时，按
PostgreSQL 的备份恢复流程使用 `database.dump`，并保留原密钥。

完成恢复并确认服务健康后，解除恢复锁定。例如：

```bash
./update.sh acknowledge-recovery --mode docker --confirm
```

## 发布新版本

先从同一源码提交构建并推送 Server、Frontend、Bootstrap 和 Nginx 镜像。每个镜像需提供
`sha-<完整提交的前 12 位>` 标签和 `org.opencontainers.image.revision=<完整提交>` 标签，然后在
GitHub 发布指向该提交的正式 Release。脚本会验证镜像平台、Git 标签和 OCI 摘要。已有升级脚本使用
正式 Release 和匹配镜像即可更新，旧版稳定清单只服务仍在使用网页更新器的实例。
